## 1. 기술 스택과 선택 이유

| 기술 | 역할 | 왜 골랐나 (초보자용 한 줄 설명) |
|------|------|------|
| Next.js 15 (App Router) | 웹 앱 프레임워크 | 화면(프론트)과 서버(API)를 한 프로젝트에서 같이 만들 수 있어서 처음 배우기 편하다. |
| React 19 | 화면 만들기 | 버튼, 목록 같은 화면 조각을 컴포넌트로 나눠 만들 수 있고, Next.js의 기본 짝이다. |
| TypeScript (strict) | 언어 | 값의 종류(타입)를 미리 검사해줘서, 실행 전에 실수를 잡아준다. |
| Tailwind CSS | 스타일 | CSS 파일을 따로 만들지 않고 클래스 이름만 적어 빠르게 꾸밀 수 있다. |
| MySQL | 데이터 저장소 | 새로고침해도 남는 진짜 DB이고, 널리 쓰여서 자료가 많고 초보자가 배우기 좋다. |
| Drizzle ORM | DB 접근 도구 | SQL을 직접 쓰는 대신 TypeScript로 DB를 다룰 수 있고, 타입과 잘 맞는다. |
| Zod | 입력 검증 | "제목 1~100자" 같은 규칙을 한 곳에 정의해 화면과 서버가 같은 규칙을 쓸 수 있다. |
| Jest + React Testing Library | 테스트 | 기능이 망가지지 않았는지 자동으로 확인해주고, 화면을 사용자 관점으로 테스트할 수 있다. |

## 2. 폴더 구조

| 폴더 | 내용 |
|------|------|
| `app/` | 페이지와 API 라우트 |
| `src/components/` | 화면 컴포넌트 |
| `src/lib/` | 서버 로직, DB |
| `src/types/` | 공유 타입 |
| `docs/` | 명세 문서 |

## 3. 전체 구조

브라우저(화면) → API 라우트(서버) → 검증(Zod) → DB 접근(Drizzle) → MySQL

- 화면은 `src/components/`의 React 컴포넌트가 담당한다.
- 화면은 DB에 직접 접근하지 않고, 반드시 `app/`의 API 라우트를 거친다.
- DB 접근 코드는 `src/lib/`에 모아 둔다.
- 화면과 서버가 함께 쓰는 타입은 `src/types/`에 둔다.

## 4. 데이터 흐름: 버튼을 누른 뒤 DB에 저장되기까지

예시: 사용자가 제목을 입력하고 "추가" 버튼을 누르는 경우 (F-01)

1. **버튼 클릭:** 사용자가 입력창에 제목을 적고 "추가" 버튼을 누른다.
2. **화면에서 1차 검증:** 컴포넌트가 Zod 규칙(제목 필수, 1~100자)으로 입력을 먼저 확인한다. 규칙을 어기면 요청을 보내지 않고 안내 문구를 보여준다.
3. **서버로 요청:** 통과하면 화면이 API 라우트로 "새 할 일 추가" 요청을 보낸다. 제목이 요청에 담긴다.
4. **서버에서 2차 검증:** API 라우트가 같은 Zod 규칙으로 다시 검증한다. 화면 검증은 우회될 수 있으므로 서버 검증이 반드시 필요하다. 실패하면 오류 응답을 돌려보낸다.
5. **DB 저장 요청:** 검증을 통과하면 `src/lib/`의 DB 로직이 Drizzle을 통해 저장을 요청한다. 새 할 일은 미완료 상태로 만든다.
6. **MySQL에 저장:** Drizzle이 요청을 SQL로 바꿔 MySQL에 보내고, DB가 새 행을 저장한다.
7. **결과 응답:** 저장된 할 일 정보가 API 라우트를 거쳐 화면으로 돌아온다. 저장에 실패하면 오류 응답이 돌아온다.
8. **화면 갱신:** 화면이 응답을 받아 목록을 최신순으로 다시 보여준다. 실패했다면 오류 안내를 보여준다.
9. **새로고침 후에도 유지:** 이후 새로고침하면 화면이 목록 조회 요청을 보내 DB에서 다시 읽어오므로 데이터가 남아 있다 (F-05).

완료 전환(F-03)과 삭제(F-04)도 같은 흐름이다. 3단계의 요청 내용만 달라지고, 대상 할 일을 구분하는 값이 함께 전달된다.

## 5. 버전별 구현 계획 (PRD 로드맵 기준)

| 버전 | 저장 위치 | 흐름에서 달라지는 점 |
|------|------|------|
| v0.1 | 브라우저 메모리 | 3~7단계 없이 화면 안에서만 처리하고, 새로고침하면 사라진다. |
| v0.2 | 서버 메모리 | API 라우트가 생긴다. 서버를 다시 켜면 사라진다. |
| v0.3 | DB (MySQL) | 위 4장의 전체 흐름이 완성된다. |
| v0.4 | DB | 필터와 수정이 추가된다. |
| v1.0 | DB | 배포한다. |

## 6. 개발 규칙

- 명세에 없는 기능을 임의로 추가하지 않는다.
- `any` 타입을 쓰지 않는다.
- 한 번에 한 기능만 작업하고, 끝나면 바뀐 내용을 요약한다.
- 테스트를 삭제하거나 건너뛰지 않는다. 테스트가 실패하면 테스트가 아니라 구현을 고친다.
- `console.log`는 디버깅 후 제거한다.
- 주석은 초보자가 이해하도록 한국어로 짧게 쓴다.

## 9. 확인이 필요한 항목

- 화면이 서버 데이터를 가져오는 방식(서버에서 미리 읽기 vs. 클라이언트에서 요청)
