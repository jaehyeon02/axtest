# PRD: Todo 앱 (초안)

- 상태: 초안
- 근거 문서: `docs/IDEA.md`

## 1. 목표

혼자 쓰는 간단한 할 일 목록 웹 앱을 만든다.

- 할 일을 추가하고, 확인하고, 완료 처리하고, 삭제할 수 있다.
- 브라우저를 새로고침해도 데이터가 사라지지 않는다.
- 기능은 MVP로 최소화하고, 버전을 나눠 단계적으로 완성한다(v0.1 → v1.0).

## 2. 대상 사용자

- 자신의 할 일을 혼자 관리하려는 개인 사용자
- 로그인이나 복잡한 설정 없이 바로 쓰고 싶은 사용자

## 3. 기능 목록

MVP 범위의 기능이다.

| ID | 기능 | 설명 | 규칙 |
|----|------|------|------|
| F-01 | 할 일 추가 | 제목을 입력해 새 할 일을 만든다. | 제목 필수, 1~100자. 새 할 일은 미완료 상태로 시작한다. |
| F-02 | 할 일 목록 보기 | 등록된 할 일을 목록으로 보여준다. | 최신순으로 정렬한다. |
| F-03 | 완료/미완료 전환 | 체크박스로 할 일의 완료 상태를 바꾼다. | 다시 체크하면 미완료로 돌아간다. |
| F-04 | 할 일 삭제 | 할 일을 목록에서 제거한다. | 삭제한 항목은 복구하지 않는다. |
| F-05 | 데이터 유지 | 새로고침해도 할 일과 완료 상태가 유지된다. | 저장 방식은 버전 로드맵을 따른다(v0.3에서 DB 저장). |

## 4. 사용자 스토리

- F-01: 사용자로서, 할 일의 제목을 입력해 추가하고 싶다. 그래야 해야 할 일을 잊지 않고 기록할 수 있다.
- F-01: 사용자로서, 제목이 비어 있거나 100자를 넘으면 추가되지 않고 안내를 받고 싶다. 그래야 잘못된 입력을 바로 고칠 수 있다.
- F-02: 사용자로서, 내 할 일 목록을 한눈에 보고 싶다. 그래야 지금 무엇을 해야 하는지 알 수 있다.
- F-02: 사용자로서, 가장 최근에 추가한 할 일이 맨 위에 보이면 좋겠다. 그래야 방금 적은 항목을 바로 확인할 수 있다.
- F-03: 사용자로서, 체크박스로 할 일을 완료 처리하고 싶다. 그래야 끝낸 일과 남은 일을 구분할 수 있다.
- F-03: 사용자로서, 완료한 할 일을 다시 미완료로 되돌리고 싶다. 그래야 실수로 체크했을 때 바로잡을 수 있다.
- F-04: 사용자로서, 더 이상 필요 없는 할 일을 삭제하고 싶다. 그래야 목록을 깔끔하게 유지할 수 있다.
- F-05: 사용자로서, 새로고침하거나 다시 접속해도 할 일이 그대로 남아 있기를 원한다. 그래야 앱을 믿고 쓸 수 있다.

## 5. 범위 밖

### 이번 MVP에서 제외 (IDEA.md의 "지금은 빼는 것")

- 로그인
- 공유
- 알림
- 마감일
- 카테고리

### 이후 버전에서 다룰 예정 (MVP 아님)

- 필터와 수정 (v0.4)
- 배포 (v1.0)

## 6. 성공 기준

- 제목 1~100자로 할 일을 추가할 수 있고, 빈 제목이나 100자 초과는 추가되지 않는다. (F-01)
- 목록이 최신 항목 순으로 표시된다. (F-02)
- 체크박스로 완료/미완료를 오갈 수 있고, 화면에 구분되어 보인다. (F-03)
- 삭제한 할 일이 목록에서 사라진다. (F-04)
- 새로고침 후에도 할 일과 완료 상태가 그대로 유지된다. (F-05, v0.3 기준)
- F-01~F-05 전체가 동작하면 MVP 완료로 본다.
- 로드맵 버전(v0.1 ~ v1.0)이 순서대로 달성된다.

## 7. 확인이 필요한 항목

- 제목 길이 1~100자를 공백 제거 후 기준으로 볼지 여부
- 삭제 시 확인 절차(확인 창)를 둘지 여부
- 완료 항목의 목록 내 위치(최신순 유지 vs. 아래로 이동)
