# TEST_CASES: Todo 앱 (초안)

- 상태: 초안
- 근거 문서: `docs/PRD.md`, `docs/TRD.md`, `docs/DATA_MODEL.md`, `docs/API_SPEC.md`, `docs/COMPONENT_SPEC.md`
- 도구: Jest + React Testing Library (`npm test`)
- 이 문서는 "무엇을 확인할지"만 적는다. 테스트 코드는 아직 없다.

## 1. 작성 규칙

- ID: API 테스트는 `API-nn`, 컴포넌트 테스트는 `UI-nn`. 결번 없이 순서대로 붙인다.
- 구분: 정상 / 에러 / 경계(경계값)
- 기능 열은 PRD의 기능 ID(F-01~F-05)를 가리킨다.
- API 테스트는 테스트용 DB(또는 DB 접근 부분을 대체한 가짜 구현)를 쓰고, 테스트마다 데이터를 초기화한다. 진짜 운영 DB는 쓰지 않는다.
- 컴포넌트 테스트에서 API 호출은 가짜(mock)로 대체한다. 네트워크에 실제로 요청하지 않는다.
- 테스트가 실패하면 테스트가 아니라 구현을 고친다 (CLAUDE.md 규칙).

## 7. 범위 밖

PRD에서 MVP 밖으로 정한 기능(로그인, 공유, 알림, 마감일, 카테고리, 수정, 필터)은 테스트하지 않는다. API-32처럼 "범위 밖 필드가 동작하지 않음"을 확인하는 경우만 예외이다.

## 8. 확인이 필요한 항목

- 공백만 있는 제목 처리(API-19, UI-11): 정해지면 기대 결과를 확정한다.
- 이미 삭제된 항목을 다시 삭제할 때 404로 할지 204로 할지(API-37)
- 404 응답 뒤 화면이 목록을 자동으로 다시 불러올지(UI-40)
- 본문이 없는 POST의 에러 코드(API-15): `INVALID_JSON`과 `VALIDATION_ERROR` 중 하나로 확정
- 삭제 확인 창을 두기로 하면 UI-16, UI-41의 흐름이 바뀐다.
- 완료 항목의 목록 내 위치가 바뀌면 API-02, UI-20을 고친다.
