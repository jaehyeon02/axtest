# COMPONENT_SPEC: Todo 앱 (초안)

- 상태: 초안
- 근거 문서: `docs/PRD.md`, `docs/API_SPEC.md` (`Todo` 타입은 `docs/DATA_MODEL.md`)
- 컴포넌트 파일 위치: `src/components/`, 페이지: `app/page.tsx`
- 화면은 DB에 직접 접근하지 않고 `docs/API_SPEC.md`의 API만 호출한다.

## 1. 화면 구성

한 페이지짜리 앱이다. 제목, 입력 폼, 할 일 목록이 위에서 아래로 놓인다.

```
┌─────────────────────────────┐
│ 할 일                        │  ← 페이지 제목
│ [ 제목 입력            ][추가] │  ← TodoForm
│ (오류 안내 영역)               │  ← ErrorMessage
│ ☐ 우유 사기            [삭제] │  ← TodoList > TodoItem
│ ☑ PRD 읽기             [삭제] │
└─────────────────────────────┘
```

## 2. 컴포넌트 트리

```
app/page.tsx
└─ TodoApp                 (상태 보관, API 호출)
   ├─ TodoForm             (F-01 입력과 추가 버튼)
   ├─ ErrorMessage         (오류 안내)
   └─ TodoList             (F-02 목록, 로딩/빈 상태 표시)
      └─ TodoItem × N      (F-03 체크박스, F-04 삭제 버튼)
```

| 컴포넌트 | 역할 | 상태 보관 |
|------|------|------|
| TodoApp | 할 일 목록, 로딩, 오류 상태를 관리하고 API를 호출한다. | 예 |
| TodoForm | 제목 입력을 받고 1차 검증 후 추가를 요청한다. | 입력값, 검증 메시지 |
| ErrorMessage | 오류 문구를 보여준다. | 아니오 |
| TodoList | 목록, 로딩 문구, 빈 목록 문구를 상황에 맞게 보여준다. | 아니오 |
| TodoItem | 할 일 한 건과 체크박스, 삭제 버튼을 보여준다. | 아니오 |

원칙: API를 호출하는 곳은 TodoApp 하나뿐이다. 나머지는 Props로 받은 값을 보여주고, 사용자 동작을 Props로 받은 함수로 알린다.

## 3. 컴포넌트별 명세

### 3.1 TodoApp

- Props: 없음
- 내부 상태

```ts
type TodoAppState = {
  todos: Todo[]; // 최신순 목록
  isLoading: boolean; // 처음 목록을 불러오는 중인지
  errorMessage: string | null; // 화면에 보여줄 오류 문구
  pendingIds: number[]; // 요청이 진행 중인 할 일 id (중복 클릭 방지)
  isAdding: boolean; // 추가 요청 중인지
};
```

- 동작
  - 화면이 처음 열리면 `GET /api/todos`로 목록을 불러온다 (F-02, F-05).
  - TodoForm의 추가 요청을 받으면 `POST /api/todos`를 호출한다 (F-01).
  - TodoItem의 체크 변경을 받으면 `PATCH /api/todos/{id}`를 호출한다 (F-03).
  - TodoItem의 삭제 요청을 받으면 `DELETE /api/todos/{id}`를 호출한다 (F-04).
  - 요청이 실패하면 응답의 `error.message`를 `errorMessage`에 담는다. 응답을 받지 못한 경우(네트워크 오류)는 6장의 문구를 쓴다.
  - 새 요청을 시작할 때 이전 오류 문구는 지운다.

### 3.2 TodoForm

```ts
type TodoFormProps = {
  onAdd: (title: string) => Promise<boolean>; // 추가 성공이면 true
  disabled: boolean; // 추가 요청 중이면 true
};
```

- 입력창과 "추가" 버튼으로 구성된다.
- 입력창은 100자를 넘게 입력할 수 있어도, 제출 시 검증 규칙(1~100자)으로 막는다.
- 엔터 키로도 제출할 수 있다.

### 3.3 ErrorMessage

```ts
type ErrorMessageProps = {
  message: string | null; // null이면 아무것도 그리지 않는다
};
```

### 3.4 TodoList

```ts
type TodoListProps = {
  todos: Todo[];
  isLoading: boolean;
  pendingIds: number[];
  onToggle: (id: number, completed: boolean) => void;
  onDelete: (id: number) => void;
};
```

- 표시 우선순위: 로딩 중이면 로딩 문구, 아니고 `todos`가 비어 있으면 빈 목록 문구, 아니면 목록을 보여준다.
- 순서는 받은 `todos` 그대로 그린다. 정렬은 서버가 한다 (최신순).

### 3.5 TodoItem

```ts
type TodoItemProps = {
  todo: Todo;
  isPending: boolean; // 이 항목의 요청이 진행 중이면 true
  onToggle: (id: number, completed: boolean) => void;
  onDelete: (id: number) => void;
};
```

- 체크박스, 제목, 삭제 버튼으로 구성된다.
- 완료된 항목(`completed: true`)은 체크박스가 체크되고, 제목에 취소선 등 시각적 구분을 준다 (PRD 성공 기준).
- `isPending`이면 체크박스와 삭제 버튼을 비활성화한다.

## 4. 사용자 동작과 결과

| 동작 | 처리 컴포넌트 | 호출 | 성공 시 결과 | 실패 시 결과 |
|------|------|------|------|------|
| 제목 입력 후 "추가" 클릭 또는 엔터 | TodoForm → TodoApp | POST /api/todos | 입력창을 비우고, 새 항목이 목록 맨 위에 나타난다. | 입력창 내용은 유지하고, 오류 문구를 보여준다. |
| 제목이 비어 있는 채로 "추가" | TodoForm | 호출 안 함 | - | 입력창 아래에 "제목을 입력해 주세요." 표시 |
| 제목이 100자 초과인 채로 "추가" | TodoForm | 호출 안 함 | - | 입력창 아래에 "제목은 100자 이하로 입력해 주세요." 표시 |
| 체크박스 클릭 | TodoItem → TodoApp | PATCH /api/todos/{id} | 체크 상태와 완료 표시가 바뀐다. | 원래 상태를 유지하고 오류 문구를 보여준다. |
| "삭제" 클릭 | TodoItem → TodoApp | DELETE /api/todos/{id} | 항목이 목록에서 사라진다. | 항목을 유지하고 오류 문구를 보여준다. |
| 화면 열기 또는 새로고침 | TodoApp | GET /api/todos | 저장된 목록이 최신순으로 보인다. | 불러오기 오류 문구를 보여준다. |

- 서버가 `404 NOT_FOUND`를 돌려준 경우(다른 곳에서 이미 삭제된 경우 등)에도 오류 문구를 보여준다. 목록을 자동으로 다시 불러올지는 8장의 확인 항목이다.
- 화면 반영은 서버 응답을 받은 뒤에 한다 (응답 전에 미리 바꾸지 않는다).
- 요청 중에는 해당 버튼을 비활성화해 같은 요청이 두 번 가지 않게 한다.

## 5. 화면 상태별 표시

| 상태 | 조건 | 보여줄 내용 |
|------|------|------|
| 로딩 | 처음 목록을 불러오는 중 | 목록 자리에 "불러오는 중..." |
| 빈 목록 | 불러오기를 마쳤고 할 일이 0건 | "아직 할 일이 없어요. 위에서 첫 할 일을 추가해 보세요." |
| 목록 있음 | 할 일이 1건 이상 | TodoItem 목록 (최신순) |
| 불러오기 오류 | GET 실패 | 오류 문구 표시, 목록 자리는 비워 둔다. |
| 동작 오류 | POST/PATCH/DELETE 실패 | 기존 목록은 유지한 채 오류 문구만 표시 |
| 추가 요청 중 | POST 진행 중 | "추가" 버튼 비활성화, 버튼 문구 "추가 중..." |

## 6. 문구 모음

| 위치 | 문구 |
|------|------|
| 페이지 제목 | 할 일 |
| 입력창 안내(placeholder) | 할 일을 입력하세요 (1~100자) |
| 추가 버튼 | 추가 |
| 추가 중 버튼 | 추가 중... |
| 삭제 버튼 | 삭제 |
| 로딩 | 불러오는 중... |
| 빈 목록 | 아직 할 일이 없어요. 위에서 첫 할 일을 추가해 보세요. |
| 입력 검증: 빈 제목 | 제목을 입력해 주세요. |
| 입력 검증: 100자 초과 | 제목은 100자 이하로 입력해 주세요. |
| 서버 오류 | API 응답의 `error.message`를 그대로 사용한다. |
| 네트워크 오류 (응답 없음) | 서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요. |
| 불러오기 실패 (응답 없음) | 할 일 목록을 불러오지 못했습니다. 새로고침해 주세요. |

입력 검증 문구는 `API_SPEC.md`의 `VALIDATION_ERROR` 메시지 예시와 같게 맞춘다.

## 7. 접근성 (기본만)

- 입력창에는 눈에 보이지 않아도 되는 라벨(`aria-label`)을 붙인다.
- 체크박스는 라벨로 해당 할 일의 제목을 연결한다.
- 삭제 버튼은 어떤 항목의 삭제인지 알 수 있는 라벨을 붙인다 (예: "우유 사기 삭제").
- 오류 문구는 스크린 리더가 알 수 있게 알림 영역(`role="alert"`)으로 표시한다.

## 8. 확인이 필요한 항목

- 서버에서 데이터를 가져오는 방식: 클라이언트에서 요청 (이 문서는 이 방식을 가정했다. TRD의 미결정 항목)
- 404가 나왔을 때 목록을 자동으로 다시 불러올지
- 삭제 시 확인 창을 둘지 (PRD의 미결정 항목)
- 완료된 항목을 목록에서 어디에 둘지 (PRD의 미결정 항목, 이 문서는 서버 순서 그대로 가정했다)
- 제목 앞뒤 공백 제거 여부 (PRD의 미결정 항목)
- v0.1, v0.2 단계(브라우저/서버 메모리)에서는 같은 컴포넌트 구조에서 TodoApp의 데이터 접근 부분만 달라진다.
